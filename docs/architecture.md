# 基础架构说明

## 设计目标

项目只搭建鉴权、实时通信、支付和系统防护四个模块的边界。业务模块之间不直接依赖彼此的实现，跨模块协作通过接口契约或 Kafka 事件完成。

## 依赖方向

```text
进程入口
  └─ 组合根
      ├─ HTTP 交付层 → 应用服务 → 领域接口 ← 基础设施适配器
      └─ Kafka 消费者 → 实时通信服务 → WebSocket 连接中心

支付模块 ──发布 payment.lifecycle.v1──> Kafka ──消费──> 实时通信模块
系统防护模块 ──作为中间件或外部调用包装器作用于边界
```

约束如下：

- 支付模块不直接调用 WebSocket。
- 实时通信模块不读取支付数据表。
- 系统防护模块不访问业务仓储。
- 鉴权模块只负责身份、令牌和会话，不管理支付或连接。
- 跨模块事件统一使用带版本的事件信封。

## 模块边界

### 鉴权

当前只实现访问令牌校验与身份上下文，登录、刷新会话和权限模型保留为下一阶段扩展点，避免在骨架期虚构用户业务。

### 实时通信

负责鉴权握手、连接登记、断开清理和按用户推送。只消费支付生命周期事件，并转换为最小的 `payment.updated` 客户端消息。

### 支付

当前只实现创建支付意图的边界；支付渠道使用本地替身，创建后发布支付生命周期事件。持久化、回调与幂等状态机留到业务阶段。

### 系统防护

提供限流、并发隔离和熔断的最小实现及中间件挂载点，具体分布式策略可通过接口替换。

## 最小接口

```text
GET    /healthz
GET    /readyz
GET    /api/v1/me
GET    /api/v1/realtime/ws
POST   /api/v1/payments
```

## 当前阶段不做

- 真实支付渠道接入、退款、订单和账务。
- 多实例 WebSocket 路由和离线消息补偿。
- 完整的权限管理后台。
- 游戏商品、激活码库存、下单发货、营销和搜索等业务。
- 复杂监控面板及生产级服务治理平台。

这些能力只保留清晰扩展点，避免基础架构提前膨胀。
